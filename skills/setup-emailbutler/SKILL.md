# Setup EmailButler
Install the whole EmailButler package, not this skill in isolation. Resolve this skill directory's real path through any registration symlink; its grandparent is the package root. Read [the recipient interface](../../docs/interface.md) before speaking to the recipient. Commands and shared resources are relative to that canonical root; the agent handles them.

## Install and connect
1. Retrieve or reuse the verified checkout from https://github.com/jcklpe/EmailButler without resetting local changes. Read its AGENTS.md and manifest. Use [Update EmailButler](../update-emailbutler/SKILL.md) for an existing installation that needs a newer version or registration migration. A plain web chat without local file access cannot install this package; report the actual host limitation.
2. Use `python3 -B scripts/install_skill.py --client codex` or `--client claude-code` to preview all registrations, then add `--execute` within the user's setup scope. This registers a fresh collection or verifies already-correct registrations. If it returns `update_required`, leave the old registration intact and invoke [Update EmailButler](../update-emailbutler/SKILL.md) to inspect and prepare the migration. Conflicting or copied installations also require inspection through Update. Setup never adds `--migrate-registrations` or `--previous-source` to replace/remove registrations. Resume connection and first-run setup only after the update workflow has resolved the migration or clearly reported its blocker. Verify fresh client discovery/reload separately from filesystem registration.
3. Inspect existing official Gmail and Outlook/Microsoft 365 connections, reuse correct ones and enable missing requested connectors through supported host controls. The user completes sign-in, consent and required host approvals. Read [host setup notes](references/host-setup.md) for connection-specific mechanics and [capability checks](references/capabilities.md) when assessing an operation. Do not substitute browser automation, a custom OAuth app or expanded permissions for an unavailable connector.
4. Independently establish the selected account identities and inspect the actual exposed schemas/permissions. Distinguish installed, connected, exposed and successfully tested. Developer-account checks do not establish recipient readiness. Do not mutate mail to test installation.
5. Locate existing private state with `python3 -B scripts/butler.py location`; use `init` only to initialize or preserve it. Existing settings and the `.email-butler` state location remain compatible across this package migration. Read [private state](../../docs/state.md). Explain briefly what is remembered and honor the user's observation-retention choice.

## Required first-run handoff
Run `scripts/onboarding.py check --input ACCOUNTS.json` for the verified selected accounts, using the same private state directory as all helpers. ACCOUNTS.json contains objects with `account` and `provider` (`gmail` or `outlook`). A new account is `required`; an unfinished cleanup is `active`. Both require loading [Bulk Triage EmailButler](../bulk-triage-emailbutler/SKILL.md) now, rather than merely offering it and silently ending setup. Start with useful, bounded examples and a concise explanation of Inbox as current work, then hand off in the same conversation. Ask at most two initial context questions against actual examples.

Bulk triage records an evidence-backed `completed`, the user's deliberate `deferred`, or a concrete `blocked` outcome for every selected account. A deferral or blocker is an addressed onboarding decision, not completed cleanup. A missing filing capability must remain visible. Do not mark all accounts complete from one account's result or a saved plan. If state cannot be saved, describe the session-only outcome and do not claim persistent onboarding.

Report installation/discovery, account coverage and the first-run outcome truthfully. Never say onboarding or cleanup is complete because files exist or a tool returned a success acknowledgement. A later [inbox review](../review-inbox-emailbutler/SKILL.md) checks this same state instead of repeating the entire installation interview. Planner, document integrations and background schedules are outside this package's scope.
